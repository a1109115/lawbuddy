## 2. 分类问题明细与根因分析

### 2.1 数据导入与解析类（P0-01、P0-02、P2-11）

#### P0-01 纯文本导入不分页

- **等级**：严重
- **影响范围**：所有 `.txt` / `.md` 材料。评测中 16 份并购协议共约 459 万字符。
- **关联模块**：`services/core/lawbuddy/documents.py`（`_extract_plain`）
- **现象与证据**：单份 257,642 字符协议 `pageCount=1`；按单次回灌 2400 字符计算，读完一份需约 107 次调用，16 份约 690 次，超过 `MAX_TOOL_CALLS=500` 上限，任务在数学上不可完成。
- **根因**：`_extract_plain` 直接返回 `[(text, "native")]`，与 PDF/DOCX 的分页管线不对称。下游检索定位、分页读取、引用页码全部按页工作，纯文本无页可定位。

#### P0-02 文件头截断导致合法文件被静默丢弃

- **等级**：严重
- **影响范围**：所有文本类文件导入，且**无任何报错提示**。
- **关联模块**：`documents.py::_decode_text_prefix` → `sniff_kind`
- **现象与证据**：16 份合同仅 15 份入库（A15 消失）；`facts.md`（245KB）返回"不支持的文件类型"。
- **根因**：固定读取 8192 字节后严格 `decode("utf-8-sig")`，末尾恰好多字节字符被切断时抛 `UnicodeDecodeError`，被判为二进制返回 `None`。

#### P2-11 工作空间重建时旧只读 blob 与新 DEK 冲突

- **等级**：中
- **影响范围**：删除并重建工作空间、密钥轮换场景。
- **关联模块**：`workspace.py`、`security.py`、blob 存储（`.lawbuddy/blobs/`）
- **现象与证据**：重建后 16 份文档全部 `parse failed`——blob 带只读属性未被清理，新 DEK 无法解密旧 blob。
- **根因**：删除流程未清除只读属性；重建时 blob 目录与密钥生命周期的归属关系未校验。

### 2.2 检索与召回类（P0-03、P1-08）

#### P0-03 短语查询 0 命中 + 多文档覆盖不足

- **等级**：严重
- **影响范围**：全部依赖检索定位的任务，是修复前"找不到条款"的直接原因。
- **关联模块**：`search.py`（`_fts_hits`、`search_pages`、`search_pages_multi`）
- **现象与证据**：
  - `"Material Adverse Effect" means` 命中 0 条；`act of God` 命中 0 条（原文 `acts of God`）。底层 SQL 直接查可得 39 条/15 份，说明是查询构造缺陷而非数据缺失。
  - 定义页在各自文档内 BM25 排名 1–10，但全案混排后前 50 条仅覆盖 8/16 份文档；工具默认 `limit=8` 时仅 2/16。
- **根因**：(a) 整串查询被当作单个 FTS5 精确短语，标点/语序/词形任一差异即整串落空；(b) 全局按页排序，同一模板条款在十几份副本中重复出现时，高分页挤占 limit，其他文档零席位。

#### P1-08 同族条款角色混淆（Target vs Parent MAE）

- **等级**：高
- **影响范围**：含对称定义的并购合同（Target/Company 与 Parent/Buyer 双侧 MAE 相邻定义）。
- **关联模块**：抽取提示词、抽取后校验（当前在评测驱动层，产品侧为 Agent 提示词）
- **现象与证据**：A05 曾把 `Buyer Material Adverse Effect` 当作目标方定义，branch 仅 0.22 并连带 8 道聚合题失败；A16 两处定义相邻均被检索命中，模型选中 Parent 侧，单份得分 0.11。
- **根因**：检索只能保证"找到 MAE 定义"，不区分定义主体；模型缺少"先判定题目问的是哪一侧、再选择对应定义"的显式步骤与校验。

### 2.3 Agent 编排与交付类（P0-04、P1-05、P1-07、P2-09、P2-10）

#### P0-04 长任务无"先落盘"机制，预算耗尽即零产出

- **等级**：严重（**当前对分数影响最大的未修复项**）
- **影响范围**：所有长卷宗任务；决定"得 0 分"与"有部分分"的分水岭。
- **关联模块**：`agent/autonomous.py`（`run_autonomous`）、任务状态机、工具提示
- **现象与证据**：WFA-LAW-001 三轮（200/900/900 轮）全部 `reason=max_rounds`，`submission/` 为空；108 次 `write_file` 全部写临时探测脚本，从未写 `deal_points.csv`/`answers.json`；LAW-014 同样 900 轮无 `judgment.json`。
- **根因**：交付物生成依赖模型自觉，提示词里的"先落盘再完善"是软约束；循环没有任何机制在任务开始创建交付骨架、在运行中周期性回写、在预算耗尽前强制输出已有结果。

#### P1-05 预算与卷宗规模不匹配

- **等级**：高
- **影响范围**：大卷宗任务可完成性。
- **关联模块**：`agent/autonomous.py`（`MAX_ROUNDS`、`MAX_TOOL_CALLS`、`PAGE_TEXT_LIMIT`、`TOTAL_PAGE_READ_CHARS`、`CONTEXT_COMPACT_THRESHOLD_CHARS`）
- **现象与证据**：修复前 500 次工具调用 < 通读 1865 页的最低需求；WFA 官方给 4 小时/题，实测 45 分钟即耗尽轮数，瓶颈在轮数与调用数而非时间。
- **根因**：常量按"中小卷宗 + 交互式任务"设定，未考虑整卷宗批量作业。

#### P1-07 跨文档聚合依赖模型自由总结

- **等级**：高
- **影响范围**：deal-point 任务 merge 分（当前均值 0.074）与 full_success（门禁 0.75）。
- **关联模块**：Agent 工具集、merge 题处理流程
- **现象与证据**：oracle 实验证明——用官方 `compute()` 对同一张表机械重算，17 道聚合题与真值 0 处不一致；即**聚合逻辑本身可完全确定性完成**，不需要模型推理。当前 merge 低分来自模型"看着表自己算"。
- **根因**：缺少"结构化表 → 确定性聚合"的工具化路径，模型被要求在上下文里心算 288 格 × 17 题的统计。

#### P2-09 多选题缺少逐项核对

- **等级**：中
- **影响范围**：deal-point 多选格；`cell_score` 为集合 F1 但单格内错选/漏选即大幅扣分，merge 中多选题 exact match 更苛刻。
- **关联模块**：Agent 抽取工作流
- **现象与证据**：基线弱项集中在多选/长文本格（`mae_co_economic` 0.688、`mae_taken_as_whole` 0.812）。
- **根因**：一次性生成全部选项，无"逐项核对原文是否提及"的二次校验。

#### P2-10 长输出生成中断连

- **等级**：中
- **影响范围**：刑事研判（8–12 被告完整判决书）、长文书生成。
- **关联模块**：`agent/model_gateway.py`、任务编排
- **现象与证据**：12 被告一次性输出时 `RemoteDisconnected`；按 4 人分批后基本成功，仍偶发单批断连。
- **根因**：单次请求输出 token 过大，云端连接被切断；产品层无分批生成、断点续传或重试-续写机制。

### 2.4 安全与边界类（P1-06）

#### P1-06 bash 旁路文档管线

- **等级**：高
- **影响范围**：证据可信度（绕过引用校验）、敏感文件边界（密钥材料）。
- **关联模块**：`sandbox.py`（`_safe_path`、`_guard_writable`）
- **现象与证据**：第 2/3 轮 Agent 用 `cat`/`type` 直读 `inputs/agreements/*.txt`（bash 分别 725/502 次，而文档工具仅 0/7 次）；并尝试打开 `.lawbuddy/dek.key`（被 `_guard_writable` 拦下）。
- **根因**：`_safe_path` 只限制在工作空间根目录内，不区分"原件区"与"工作区"；模型在检索失效时自然转向 shell 绕过。

### 2.5 工程机制类（P2-12）

#### P2-12 缺少 LAW 域自动化回归评测

- **等级**：中
- **影响范围**：所有优化的效果可持续性与防回退。
- **关联模块**：`services/core/evals`、CI
- **现象与证据**：本次评测全部为一次性 `_wfa_*.py` 脚本，无法纳入日常回归。
- **根因**：项目评测集（m2–m5）未覆盖"大卷宗、多文档、英文合同、多被告"这四类真实压力场景。

### 4.2 P0-04 交付物骨架与周期回写机制（最高优先级）

- **等级**：严重｜**责任人**：Agent 组｜**工时**：5 pd｜**上线节点**：T0 + 2 周（M2）
- **交付物**：`autonomous.py` 交付物管理器 + 任务 Schema 扩展 + 单元评测
- **实现路径**：
  1. **声明式交付契约**：任务创建时允许携带 `deliverables`（文件名 + Schema/模板路径）。任务启动即在 `submission/` 生成骨架文件（空表头 CSV、模板化 JSON），并把"骨架已存在"写入系统提示。
  2. **周期回写钩子**：每 N 轮（默认 10）在循环内注入一条轻量提示："当前已确认结论请立即合并写回 `submission/`，不要等全部完成"；工具层提供 `deliverable_patch`（按主键 upsert CSV 行 / 按被告 upsert JSON 节点），避免整文件重写。
  3. **预算耗尽兜底**：`max_rounds`/`max_calls` 触发时，循环进入"收尾模式"：禁止新开检索，仅允许将已确认内容写回交付物后结束。
  4. **中断注入测试**：模拟在第 30%/60%/90% 轮数处中断，验证交付物始终存在且可解析。
- **校验方法**：WFA-LAW-001/014 各跑 1 轮完整 Agent；在任何时刻检查 `submission/` 非空且 `verify.py` 可读出分数（允许低分，不允许 0 交付）。
- **兼容性**：`deliverables` 为可选字段，不影响现有任务；RPC 契约改动需同步 `packages/contracts`、preload 与主进程（遵循 AGENTS.md 双端同步要求）。

### 4.3 P1-07 聚合计算工具化

- **等级**：高｜**责任人**：Agent 组 + QA 组｜**工时**：4 pd｜**上线节点**：T0 + 2 周（M3）
- **交付物**：`table_aggregate` 工具（声明式聚合 DSL）+ 评测
- **实现路径**：
  1. 新增只读工具：输入为已落盘的结构化表（CSV/JSON）+ 聚合描述（`count_by` / `filter_eq` / `compare_sets` / `numeric_threshold` 等 6–8 种算子），输出为确定值。
  2. 工具内部直接复用官方 `verify.compute` 同语义的纯 Python 实现（不引入第三方依赖，保持离线可跑）。
  3. Agent 提示引导：merge 类问题一律"先查表、再调工具、禁止心算"。
  4. 结果与表内容做一致性校验（`consistency` 指标防"表 A 答 B"）。
- **校验方法**：用官方真值表驱动工具，17 道聚合题输出与 `answers.json` 必须 0 处不一致（该性质已在 oracle 实验中证明可达）；再对模型产出的表复算，merge 分数应与官方评分完全一致。

### 4.4 P1-06 bash 原件区隔离

- **等级**：高｜**责任人**：安全组｜**工时**：3 pd｜**上线节点**：T0 + 2 周（M2）
- **交付物**：`sandbox.py` 路径分区策略 + 安全评测
- **实现路径**：
  1. 工作空间内划分只读原件区（`inputs/`、`.lawbuddy/`）与工作区（`work/`、`submission/`）；bash 的读操作对原件区默认拒绝，提示"请使用 document_search / document_get_pages"。
  2. 保留显式白名单机制（任务级 `allowReadPaths`），供确有需要的调试场景使用；密钥材料（`dek.key` 等）维持现有 fail-closed，不新增任何读通道。
  3. 拦截事件写入审计（仅路径与动作，不写文件内容）。
- **校验方法**：`m3_security` 新增用例——bash 读 `inputs/` 被拒、读工作区正常、`documentIds` 检索不受影响；重跑 LAW-001 观察 bash 直读原件次数降为 0。
- **风险联动**：见 §6 R2（可能影响既有依赖 shell 的工作流）。

### 4.5 P1-08 条款角色消歧

- **等级**：高｜**责任人**：检索组 + Agent 组｜**工时**：4 pd｜**上线节点**：T0 + 4 周（M4）
- **交付物**：角色感知抽取提示模板 + 抽取后校验器 + 评测
- **实现路径**：
  1. 抽取提示增加显式两步：先列出片段中**全部** MAE 定义（含前缀，如 `Parent`、`Buyer`、无前缀），标注各自主体；再按题目主体（Target/Company）选择对应定义作答。
  2. 抽取后校验：若答案片段来源为带买方前缀的定义而题目主体为目标方，标记 `needs_human`（沿用现有证据状态机），不静默给确定答案。
  3. 检索侧辅助：`documentIds` 限定 + 多路锚词已保证两侧定义都能命中，消歧放在语义层而非检索层。
- **校验方法**：构造含双侧定义的 A05/A16 专项用例，目标方 18 格 branch 从 0.22/0.11 提升至 ≥0.80；全部结论可回跳原文页码。

### 4.6 P2-09 多选题逐项核对

- **等级**：中｜**责任人**：Agent 组｜**工时**：3 pd｜**上线节点**：T0 + 5 周（M4）
- **交付物**：多选校验工作流 + 评测
- **实现路径**：多选字段采用"候选生成 → 逐项核对"两段式：先给候选集合，再对每个选项独立问"原文是否明确包含该情形（给出原句）"，仅保留有原文证据的选项；无证据项进入 `needs_human` 而非硬选。
- **校验方法**：对基线弱项字段（`mae_co_economic` 等）复测，多选格 F1 均值从 0.69 → ≥0.85；引用全部通过 `verify_quote` 校验。

### 4.7 P2-10 长输出分批与断点续写

- **等级**：中｜**责任人**：Agent 组｜**工时**：3 pd｜**上线节点**：T0 + 5 周（M4）
- **交付物**：`model_gateway` 输出长度自适应 + 续写重试 + 刑事任务分批器
- **实现路径**：
  1. 按输出规模自适应分批（如每批 ≤4 个实体/≤4000 token），批间通过 Schema 合并而非自由文本拼接。
  2. `RemoteDisconnected`/超时触发有限重试（指数退避 ≤3 次）；重试时携带已生成部分要求"续写"而非重来。
  3. 合并后做 Schema 完整性校验（8/12 被告键齐全、roles 键与 charges 一致）。
- **校验方法**：LAW-016（12 被告）连续 3 次运行交付完整率 100%；断连注入测试下最终交付物仍可解析。

### 4.8 P2-11 blob 与 DEK 生命周期修复

- **等级**：中｜**责任人**：文档组 + 安全组｜**工时**：2 pd｜**上线节点**：T0 + 4 周（M4）
- **交付物**：工作空间删除/重建流程修复 + 评测
- **实现路径**：删除工作空间时先 `chmod` 清除只读属性再删除 blob；重建时校验 blob 与当前 DEK 的匹配关系，不匹配则明确报错并引导重新导入原件（不静默 `parse failed`）；全程不降级为明文存储。
- **校验方法**：删除→重建→重新导入 16 份文档全部 `ready`；`m3_db_reliability`、`m3_security` 回归通过。

### 4.9 P2-12 LAW 域回归评测常态化

- **等级**：中｜**责任人**：QA 组｜**工时**：5 pd｜**上线节点**：T0 + 6 周（M5）
- **交付物**：`evals/wfa_law/`（任务镜像 + 驱动 + 评分 + 报告）+ CI 任务
- **实现路径**：将本次 22 个任务的驱动脚本产品化为可重复评测包（任务输入快照、官方 verify 副本、统一驱动、结果 JSON）；提供"快速档"（2 个代表任务，进 CI）与"全量档"（22 任务，双周定时）。
- **校验方法**：同一 commit 两次运行结果一致（评分确定）；历史结果可对比并输出回归 diff。
