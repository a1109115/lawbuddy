阅读前的一段说明

这份稿子里有三种数字，请分开看。

第一种是项目已实现的工程实数：202 个 RPC 方法、19 张新表、28/28 确定性 gate、51/51 前端单测，来自仓库与 2026 年 11 月产品介绍，可在代码和评测报告里逐条复核 S16。第二种是公开权威统计：律师人数、备案数量、司法文件发布日期，均标来源与日期 S1–S8。第三种是本计划的测算假设：客户数、定价、收入、成本、融资额，全部是待验证的规划值，不是历史业绩，也不是业绩承诺。

凡涉及团队履历、公司主体、既有营收、融资条款等仓库里查不到的事项，一律写【待补】，未代为编造。文末「待补清单」把待拍板的事集中列了出来。

一、执行摘要

LawBuddy 回答的不是「AI 能不能写法律文书」，而是「这份 AI 写出来的东西，律师敢不敢签字」。

它是一台装在 Windows 上的本地法律工作台：案卷、合同、文书三条工作流都在本机加密库里跑，原件只读由代码强制；每条事实性结论必须绑定「文档 + 页码或条款号 + 原文片段」，经 verify_quote 规范化比对后才能标为 supported；比对不上、OCR 置信度低、原文打架或文档换版，一律落进 needs_human / conflict / stale，交给律师裁决，而不是继续显示成已支持事实 S16。点一下引证芯片，右侧原文跳到那一页并高亮。这套机制不靠模型自律，靠数据结构和流程守门。

已经做出来的东西比一般 PPT 项目扎实。 v0.1.0 于 2026-11-05 首次开源 S16；三层架构（Electron 桌面端 / packages/contracts 共享契约 / Python Core）通信只走同一份 Schema；Core 注册方法由 159 增至 202，存储从 V48 迁到 V54，新增 19 张表与 1 列；Hermes 升级 28/28 gate、201 条断言，Harness 16/16，前端 51/51，密钥扫描源码 184 / 构建 72 文件 0 命中；NSIS 安装包与签名链路实跑，win-unpacked 146 文件 0 命中，SBOM 清点 243 个组件 S16。产品介绍里的示例案件（57 份文档、约 305 页）跑完 7 项任务、92 次工具调用、8 分 7 秒，36 条证据逐条标注，4 个争点因原文不足转为待补材料 S16——注意这是演示口径，不是基准评测，别拿去当性能承诺。

时机对得上。 司法部 2025-09-08 国新办发布会给出：全国律师 83 万人、律所 4.5 万家，每年办理诉讼和非诉讼法律事务 1500 多万件，为 90 多万家机关企事业单位担任法律顾问 S1。2026-09-07，最高法发布首部涉人工智能司法裁判规则文件《关于依法审理涉人工智能纠纷案件的意见》，5 部分 24 条，把「AI 幻觉」侵权列入裁判规则 S5。更直接的是 2026 年 11 月安庆市律协发布的三份 AI 应用规范：工作秘密、商业秘密等核心涉密数据仅可在数据不出本所的本地部署系统中处理；对外出具的诉讼文书、法律意见书须承办律师逐条实质审核、签字确认；AI 生成的法条、判例、案件数据须调取官方数据库全文比对，不得以检索摘要作为核验依据 S6。这几条几乎是把 LawBuddy 的设计前提写成了行业自律条文。

但这个项目现在还不能按「成熟产品」卖。 产品介绍第 22 页把话说得很清楚：默认运行时仍是 v2，V3 需显式开启，5 个新开关里 4 个默认关闭；真实模型三次复测（C-04）、22 题全量回归（C-05）、效率报告（C-06）、候选包与 20+50 任务灰度、全量切换与回滚演练均未开始，整体进度 13/21；两轮 WFA 实跑 composite 从 84.42 掉到 11.98，守门未通过；README 里也写明「目前由个人业余维护」S16。所以本轮的目标不是规模化销售，是把工程可用性补完，并拿到第一批愿意为「可复核」付钱的机构客户。

本轮诉求（建议值，待项目方拍板）： 融资 300–500 万元、18 个月跑道，钱花在三处——把 V3 跑稳并通过真实模型回归、拿下 10–20 家种子客户并形成可出示的复核留痕证据、把许可与合规边界清理干净。具体金额、是否接受外部股权、目标估值均见【待补 1】。

一句话判断：这条赛道稀缺的不是模型能力，而是出错以后能不能查到第几页。LawBuddy 已经把这件事写进代码；商业化要解决的是谁为它付钱、凭什么信它、以及怎么在开源前提下收得到钱。

二、痛点与市场

2.1 三道绕不过去的坎

幻觉是执业责任，不是产品瑕疵。 美国 Mata v. Avianca 案里，律师把 ChatGPT 生成的 6 个不存在的判例提交法院，被罚 5000 美元；2025 年北京通州法院一起案件中，代理律师提交 AI 生成的虚假案例被法官当场识破，该案入选人民法院案例库；2026 年 2 月杭州法院在 AI 幻觉引发的不正当竞争案中明确，使用者负「内容审核」与「显著标识」双重义务，技术中立不能免责 S14。中国经济网 2026-09-28 引述执业律师的话更实在：复核比学提示词更重要，用工具时应当要求标注法规、案例来源，便于人工核验 S2。

案卷不能往外传。 《律师法》第 38 条的保密义务、网络安全法 / 数据安全法 / 个人信息保护法构成底层约束 S14。安庆规范把执业数据分三级：国家秘密不得输入任何 AI 系统；核心涉密数据只能在「数据不出本所」的本地部署系统处理；一般信息未经脱敏不得输入公有云；发生数据泄露须 3 个工作日内书面上报 S6。这条规定把「本地部署」从加分项变成了部分场景的准入项。

交付物得能进正式流程。 律师要的是带脚注、修订痕迹、可继续用原格式编辑的 Word，不是聊天窗口里的一段文字；还要能说明哪句出自哪页。传统复核是通读一遍，AI 时代的复核应当是照着引证跳页看一遍——这个转变决定了工具值不值钱。

还有个结构性落差值得注意：有第三方汇总的 LexisNexis 调研称，中国内地法律专业人士 AI 使用率从 2024 年 68% 升到 2025 年 88%（律师及实习律师 93%），但律所层面常规化应用仅 28%，47% 受访者称所在律所计划两年内推行 AI 战略 S12。该数据系二手转引，未取得原始报告核验，仅作趋势参考。 若方向属实，说明大量律师在用个人账号零散地用，机构统一部署、统一审计的缺口正是产品机会。

2.2 市场有多大：先把口径吵清楚

可核定的付费基数来自官方：83 万律师、4.5 万家律所、年 1500 多万件法律事务、90 多万家单位法律顾问 S1。中国经济网 2026-09-28 补充了结构判断：截至 2025 年底执业律师超 80 万、律所约 4.5 万家，预计 2026 年底突破 90 万；但业务增速放缓、同质化、低价内卷、两极分化加剧 S2。人多了、单案收入压力大，效率工具从锦上添花变成降本刚需——这是本计划最看重的市场信号。

供给侧的门槛则在消失。国家网信办 2026-01-09 公告：截至 2025-12-31 累计 748 款生成式 AI 服务完成备案、435 款应用或功能完成登记，2025 年全年新增 446 款备案 S3；《国家信息化发展报告（2025 年）》给出生成式 AI 用户规模 6.02 亿人、同比增长 141.7% S4。模型本身不再是壁垒。

三、产品与服务

3.1 结构与边界

三层架构，跨进程通信只走 packages/contracts 一份共享 Schema S16：

层技术职责
apps/desktopElectron 44、React 19、TypeScript、Zustand、TipTap窗口、IPC、Python Core 子进程生命周期；渲染层新增 5 个运行时面板
packages/contracts共享类型契约（唯一来源）本轮扩容约 799 行：声明式交付契约、运行时/恢复/诊断/会话/学习/插件 Schema 与 6 类事件
services/corePython 3.12、LangGraph、SQLCipher、PaddleOCR / RapidOCR / RapidTable阅卷 Agent、合同审查、文书生成、OCR、引用校验、加密存储、审计；stdin/stdout 换行分隔 JSON-RPC 2.0

模型不直接碰文件，只拿到解析后的文本与来源坐标；文件工具、glob、grep、bash 一律拒绝直读 inputs/、blobs/、.lawbuddy/，Shell 拦截 .. 逃逸与绝对路径 S16。模型由用户自行配置（DeepSeek / 智谱 / 千问 / Kimi 或任意兼容端点），API Key 按服务商隔离、经 DPAPI / Keychain / Secret Service 保护，fail-closed，界面只显示「已配置」S16。这条「用户自带 Key」的设计，同时是合规优势和收入天花板，第七章会再说到。

3.2 三条工作流

  • 案卷阅卷：LangGraph 自主 Agent Loop，自己拆任务清单、调工具、派子代理、核验结论；每一步写入事件流，可中断、按检查点续跑、不重复已完成调用。报告采用「结论—原文出处—证据状态」三段式，先报缺失材料清单，再谈分析 S16。
  • 合同审查：原件只读 → 审查概览定立场与强度 → AI 生成 + 人工增删的审查清单，保存即冻结版本 → 按等级归并风险结果，每条风险带条款号、页码与原文片段，可跳页高亮。确定性规则只声明「检测到／未检测到」，语义判断留给律师 S16。
  • 文书生成：内置常用范本并支持自带模板；事实槽位区分 case_evidence / user_confirmed / pending_verify，没有原文引证的事实拒绝正式填充；成稿为 DOCX / XLSX / PPTX，支持原格式在线编辑，脚注与修订痕迹保留，外发前需明确授权 S16。

3.3 真正当作壁垒的那部分

引用门禁不是提示词，是数据模型加流程约束：结论文本 → 绑定文档标识 + 页码/条款号 + 短原文片段 → verify_quote 规范化后做原文子串比对（仅容忍空白、断行、全半角差异）→ 按结果写入 Claim Ledger 四态 S16。OCR 更正、文档换版或引用重验后，旧 Claim 一律标 stale；导航摘要只放 claim_id 与 source_ref，不得充作 supported 依据 S16。

运行时这一版补的是「跑得完、断得开、追得回、可回滚」：任务契约编译器把「20 份协议 × 15 个问题」编译成 300 个唯一工作单元，重复编译不增不减；工作账本持久化无淘汰，fixture 实测 1,865 页 / 320 答案格 / 300 证据 / 60 争点零淘汰；交付控制器在任务启动即写好骨架，30% / 60% / 90% 三个时点强行中断仍得到行全集 100%、可解析的正式文件；工具 Journal 七态，非幂等调用崩溃后标 unknown，由人在恢复中心三选一（标记已发生 / 重新执行 / 忽略），系统不擅自重放；39 件工具登记 6 种副作用与 4 种并发作用域，插件与 MCP 默认禁用、默认禁网，5 个运行时开关可独立回滚 S16。

壁垒要说克制些。 这不是专利壁垒，也没有自有法律数据库（裁判文书、法规库都没有），开源还让「卖软件副本」变得困难。竞品能抄功能，难抄的是审计语义、版本失效链和交付确定性；但真正能守住的护城河，得靠客户复核留痕形成的证据、行业规范的适配深度、以及技能与插件生态慢慢攒。现阶段把它称作「机制领先」比称作「护城河」更准确。

四、商业模式

4.1 不卖软件副本，卖「机构敢批准用、出事能举证」

Apache-2.0 开源意味着任何人可以自己编译、审计、二次分发。硬收 License 费既不现实，也与项目信任叙事冲突。收入应当落在开源版之外、机构真正愿意掏钱的四层：

层级对象建议价格（待试点验证）提供什么
社区版个人律师、学生、法援、评估者免费，Apache-2.0完整核心能力、用户自配模型 Key；用于获客、审计透明与生态
专业版个人律师、小团队建议 1,800 元 / 席位 / 年评审就绪包、技能包、模型健康面板、优先更新
团队/机构版律所诉讼团队、企业法务建议 3.6 万元 / 所 / 年（区间 3–8 万）集中配置与统一密钥管理、审计导出、权限预设、部署培训、律协规范映射表
合规与交付服务有内网 / 涉密要求的机构建议 12 万元 / 项目（区间 10–30 万）私有化部署、内网与等保适配、审查清单与模板定制、复核 SOP、第三方安全评估配合

定价锚点参考：第三方产业链测算给 ToP 约 3,000–10,000 元 ARPU、ToB 约 5–20 万元 ARPU S10；中小律所定制研发年成本 20–50 万元，相当于一名律师一年的创收 S15。两相对照，机构版 3.6 万元/年应当能被「不自建」的账算得过来。

有三条边界要写进合同，也写进商业承诺：不代收模型 Token 费（用户自配 Key，模型成本与数据外发责任清晰）；不接触、不沉淀、不变现客户案卷数据（无默认上传、无外部遥测、诊断包由用户本地导出且不含原文与查询词）S16；不承诺 AI 输出可直接作为法律意见（产品定位为辅助工具，正式交付必须执业律师核实签字）S16。不代收 Token 意味着毛利高、合规清爽，但也意味着没有用量型收入，客单价上限清晰——这是模式选择，不是疏漏。

4.3 谁会先掏钱

按购买动机排序，而非按机构规模排序：

  1. 有合规硬约束的诉讼团队——涉密、涉个人信息、金融与国企类案件，本地部署不是偏好而是准入条件 S6。
  2. 企业法务中的合同与争议岗位——审查清单冻结版本、风险带条款号、结果可直接进会，采购理由比「效率」更硬。
  3. 法律援助与教学机构——过程可回放、结论可复核，适合方法论示范，客单价低但口碑与案例价值高 S16。

相反，中小律所整体数字化意愿偏弱，有行业方案直接指出「对大部分中小律所来说有无数字化系统并不影响业务创收，数字化被定义为非刚需」S15。所以不要拿「提效」当主打话术，先拿「合规准入 + 复核可举证」切进去。

5.2 差异化三句话

  • 通用 Agent 交付结果，LawBuddy 交付可复核、可恢复、可回滚的结论：出处绑定、四态标注、跳页高亮、审计留痕 S16。
  • 别人的「可溯源」多指推理路径与检索来源，LawBuddy 指的是案件原文的具体页码与条款号，且引用片段要回原文做子串校验 S16S6。
  • 别人的输出是聊天记录或摘要，LawBuddy 任务一启动就生成交付骨架，中断也交出可解析的正式文件 S16。

5.3 劣势也要摆出来

无自有法律数据库与判例库；仅支持 Windows 10/11（密钥环依赖 DPAPI）；单人业余维护，巴士因子为 1；V3 尚未默认、真实模型效果未验证；无品牌、无销售渠道、无客户案例；并且存在一处必须优先处理的许可瑕疵：README 第 138 行明确，services/core/seed/skills/@team/case-file-review/references/cause-of-action-wiki/ 下的案由知识库系对第三方出版物的结构化整理，其自身声明「仅供个人学习、研究使用，请勿用于商业目的」，不适用 Apache-2.0 的商业使用许可，商业场景须自行取得授权或从项目中移除该目录 S16。这一条若不处理，任何商业版授权都有瑕疵，尽调阶段必然被问到。
