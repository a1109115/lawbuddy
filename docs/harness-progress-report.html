已落地

work_contract.py · V50 迁移

统一预算 = 时间与额度

已落地

轮次、工具调用、模型调用、Token、实际耗时都记在同一个本子上；中断后接着算，不会“重开一局又满血”。

budget.py · scheduler.split_budget

调度器 = 工头派活

已落地

优先做能解锁别人的活，再做没试过的活；某个格子连续失败就标“要人看”，不拖垮整个任务。

scheduler.py

交付控制器 = 收尾装订员

已落地

到点就补齐整张表的行、原子写文件、算派生汇总、写完再读回来校验；交不齐会明确显示“部分交付”。

delivery_controller.py · aggregate.py

上下文组装器 = 只发当前一页资料

已落地

每次只把当前格子需要的证据和缺口给模型，不再把整本卷宗一遍遍塞进对话，省 Token 也更准。

context_builder.py

工作型子代理 = 临时助手

已落地

助手只做指定的格子、只写暂存区，不能直接改正式交付物；重复提交会被编号去重。

worker.py · concurrency.py

已落地

autonomous.py 检索范围键 · search.py

需要特别提醒的三件事

1. 代码默认已经是 V2

带交付物的新任务默认按 V2 运行（agent.runtimeVersion 默认 v2），但真实模型验收和灰度都还没做。

建议：在 C-04/C-05 完成前，把正式工作区的运行时开关显式设为 v1，或只在隔离工作区使用 v2。

2. “测试全绿”只覆盖确定性范围

16 项 Harness gate、迁移 7 用例、静态检查都过了，说明机制正确；但分数、Token 效率、长任务稳定性还没有真实数据。

不要把确定性通过当成“改造目标已达成”。

3. 安装包尚未更新

仓库里的 release 安装包和 dist_core 都是 11 月 6 日的产物，不包含本次 Harness 改造。

对外演示或试用前必须重新执行打包与冒烟流程。

4. 仓库里有大量调试脚本

根目录约 70 个 _wfa_*.py 调试脚本尚未清理，也没有纳入版本管理。

不影响功能，但会影响交付整洁度，建议在 D-01 前归档到临时目录。
